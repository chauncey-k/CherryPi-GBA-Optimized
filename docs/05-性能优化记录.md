# 性能优化记录 · smc-live 2026-10-17

## 问题与证据

用户运行特定宝可梦改版时，观察到个位数显示帧、模拟速度不足、声音断续。更改过滤设置未解决。实板日志证实 ARM 动态重编译已开启，CPU 时钟408MHz；不是通过更换操作系统解决。

smc-guards 实板：7280采样，RAM清空47439次，RAM ARM翻译261250次。四个恢复PC（030020a0、030020a8、030020b0、030020b8）记录47352次失效，约占99.82%。缓存占用远小于768KiB；反汇编存档确认游戏用STM复制音频指令模板，涉及48个字。

例如 `e08c6006`（ADD r6,r12,r6）和 `e0877004`（ADD r7,r7,r4）之间切换；`505cc006`（SUBSPL r12,r12,r6）和 `e05cc006`（SUBS r12,r12,r6）之间切换。它们改变执行语义，不能忽略自修改后继续运行旧指令。

## 实现

gpSP 的 cpu_threaded.c 对这些位置生成所有已支持模板的原生分支。执行时读取当前指令字并选择分支，保留NZCV。arm_stub.S只对来源和完整STM组均通过验证的写入保留缓存；未支持写入仍清空。Thumb重叠、不满足动态生成条件或未知运行时指令都走原失效路径。未知分支会保存当前GBA PC和原NZCV后重试，不能任意选一个模板。

此前修复的标记清理和同值写入也保留。即时存档安全修复、原生设置、快捷菜单和两类存档提示已在此程序内；没有提高CPU频率，没有降低采样率或改跳帧来换速度。

## 实板结果

最终发布程序SHA256：`923fb7fff27a3f0eb2bfc4b3599a62dd0149a478444ee8a521e49a563589f250`。

- 最新5542样本、零丢失，LIVE_SMC_RETAINED=44848，证实保留缓存路径实际命中。
- RAM清空261次；RAM ARM翻译3706次、RAM Thumb444次。
- TRACE第12～36窗口多数60模拟帧，一个窗口58；第37～39为57/56/55，随后恢复60。
- ARM翻译函数墙上时间采样占比从24.02%降为0.56%。

每窗口是100个送达采样，约1秒，不是严格定时帧率仪。两次运行时长与菜单停留不同，不根据总计算精确提速倍数；模拟帧数不等于LCD实显帧数。用户确认明显改善、只偶尔卡顿。

剩余261次清空中228次来自另一组自修改位置（0300237c/84/90/98）。这不是取消失效检查的理由。先保存本稳定基线，再在复现明确的场景单独优化。其他游戏只有使用相同位置及模板时才可能直接受益，不能宣称普遍加速。
